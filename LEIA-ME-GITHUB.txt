FOGOSEGURO — PUBLICAÇÃO NO GITHUB PAGES
=======================================

Este pacote publica a página do FogoSeguro pelo GitHub Pages. O GitHub Pages hospeda apenas arquivos estáticos; por isso, login, banco de dados e uploads usam uma API no Cloudflare Workers, com banco D1 e arquivos no R2. O endereço do site será GitHub Pages; o banco e a API continuam no Cloudflare.

O repositório já inclui GitHub Actions em `.github/workflows/pages.yml`: cada envio de alterações para a branch `main` publica automaticamente a pasta `site/`.

1. ENVIAR OS ARQUIVOS AO GITHUB
-------------------------------
1. Crie um repositório GitHub (por exemplo, `fogoseguro`).
2. Envie o conteúdo deste ZIP para a raiz do repositório, mantendo as pastas `site/`, `api-cloudflare/` e `.github/`.
3. No GitHub, acesse Settings > Pages e selecione GitHub Actions como fonte de publicação.
4. Aguarde a execução do workflow `Publicar FogoSeguro no GitHub Pages`. O endereço será parecido com `https://SEU-USUARIO.github.io/NOME-DO-REPOSITORIO/`.

Você pode enviar os arquivos com GitHub Desktop ou Git. Exemplo, dentro da pasta extraída:

  git init
  git add .
  git commit -m "Publica FogoSeguro"
  git branch -M main
  git remote add origin https://github.com/SEU-USUARIO/NOME-DO-REPOSITORIO.git
  git push -u origin main

2. PREPARAR A API E O BANCO CLOUDFLARE
--------------------------------------
A API precisa de um Worker próprio. No terminal, entre na pasta `api-cloudflare/` e execute:

  npm install
  npx wrangler login
  npx wrangler d1 create fogoseguro-db

Copie o `database_id` informado pelo Wrangler para o campo `database_id` em `api-cloudflare/wrangler.jsonc`, substituindo `COLE_AQUI_O_DATABASE_ID_GERADO_NO_CLOUDFLARE`.

Crie o bucket de arquivos e aplique as tabelas:

  npx wrangler r2 bucket create fogoseguro-media
  npx wrangler d1 migrations apply fogoseguro-db --remote

Configure os valores em `wrangler.jsonc` antes de publicar:

- `ALLOWED_ORIGIN`: origens autorizadas separadas por vírgula, sem caminho nem barra final. O arquivo já inclui GitHub Pages e os domínios Cloudflare que você informou.
- `PUBLIC_API_URL`: URL base do Worker, sem barra final. O nome do Worker deste projeto é `protecextintores`; o Wrangler exibirá a URL com o subdomínio da sua conta.
- `ADMIN_USER`: usuário inicial, `admin` por padrão.

Publique e configure a senha inicial como segredo:

  npx wrangler deploy
  npx wrangler secret put ADMIN_PASSWORD

Informe uma senha exclusiva com pelo menos 5 caracteres. Não a coloque em `wrangler.jsonc`, no site nem no repositório. Depois, confira a URL exibida pelo Wrangler e use-a como `PUBLIC_API_URL`.

3. LIGAR O SITE À API
---------------------
Abra `site/config.js` e defina a URL do Worker, sem barra final:

  window.FOGO_API_BASE_URL = 'https://protecextintores.SUA-CONTA.workers.dev';

Salve e envie a alteração ao GitHub (`git add .`, `git commit -m "Configura API do FogoSeguro"`, `git push`). O GitHub Actions publicará a versão atualizada. Recarregue o endereço do Pages. Entre como `admin` usando a senha secreta definida acima.

A URL do Worker precisa corresponder ao `PUBLIC_API_URL`; cada origem usada no site precisa estar listada em `ALLOWED_ORIGIN`, sem o caminho `/NOME-DO-REPOSITORIO/` e sem barra final. Separe várias origens por vírgula.

DADOS E ARQUIVOS
----------------
- D1 armazena usuários, clientes, vendedores, serviços, pedidos, produtos, configurações e preços.
- R2 armazena logos, imagens e vídeos enviados pelo painel.
- A migração 0002 cria os acessos de vendedores e o controle de aceite dos serviços. Sempre execute novamente `npx wrangler d1 migrations apply fogoseguro-db --remote` antes de publicar a API após receber novas migrações. Depois publique com `npx wrangler deploy`.
- O banco começa vazio, com catálogo inicial de tipos e preços sugeridos editáveis. Para levar os dados do site antigo, baixe um backup JSON em Configurações e restaure-o no novo painel. Recrie as contas dos funcionários; senhas antigas não são exportadas.
- Faça backups frequentes pelo painel e mantenha acesso à sua conta Cloudflare. O estoque, preços sugeridos, novas capacidades comuns de CO₂ e contas de vendedores são armazenados no D1.
- As senhas são guardadas como hash; o segredo inicial do administrador fica no Cloudflare Secret e não no código. A sessão do painel persiste entre recargas e abas até usar Sair.
- O Worker usa D1/R2 e quotas de Workers. Consulte os limites/preços atuais no painel Cloudflare.

O arquivo `site/config.js` começa sem URL de API. Sem configurá-la, o site público carrega, mas os recursos que dependem de banco/login não funcionarão. A configuração da API é necessária para manter os dados salvos e permitir login.
